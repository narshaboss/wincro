# GPT 플레이 무제한 세션·연속 조작 검수

작성일: 2026-11-03 (한국 시간).
코드 기준: `83a40e740a5fa11446da9892f140b1c0cb5aa425`.
최종 CI: [Regression Check 41481433914](https://github.com/narshaboss/wincro/actions/runs/41481433914), 성공.

## 원인

- 실제 최근 세션은 행동 49회, 남은 시간 0초였다. 500회 소진이 아니라 기존 15분 제한으로 중단됐다. 질문·일시정지 시간도 포함되던 구조였다.
- 동일 세션의 장치 진단은 `timed_input_gl1=False`였다. COM7에서 키 입력 없이 확인한 응답도 `PING -> PONG`, `GL1 -> ERR:UNKNOWN_CMD`였다. Python 패키지 누락이 아니라 보드 펌웨어 기능 부족이었다.
- 기존 `key`는 짧은 KQ 탭이다. 이를 방향 이동에 반복 사용하고 매번 GPT 판단·새 화면 도구 호출을 기다리면 입력 유지 시간과 모델 왕복 지연이 함께 병목이 된다.

## 구현

- GPT 플레이의 기본 시간·행동 횟수 제한을 제거했다. `max_actions`와 `remaining_seconds`는 무제한일 때 JSON `null`이며 UI에는 `실행 한도 없음`으로 표시한다.
- 시도 10회와 정상 GPT 턴 20회 제한도 제거했다. 진행이 없는 연속 턴 차단, 중지·포커스·저장 무결성 검사는 유지한다.
- GPT 플레이 전용 실행기는 전체 시간·이벤트 수로 끊지 않는다. 녹화 분석 실행기의 기존 제한과 도구 권한은 그대로다.
- `play_control`은 최대 8구간의 방향·스킬 입력을 한 호출로 실행한다. 각 구간은 최대 2개 게임 키, 50~1000ms이며 입력 유지 시간의 합계는 최대 2초다. 통신·저장·관찰 지연을 포함한 전체 왕복이 2초 이내라는 뜻은 아니다. 구간 사이에 GPT를 호출하지 않는다.
- 같은 응답에 실행 영수증과 새 결과 화면을 함께 전달한다. 다음 행동은 이 화면으로 판단할 수 있다. 추가 `play_observe` 왕복이 필수였던 흐름을 줄였다.
- 탐색·재사용 구간·후보 재생·저장된 GPT 구간 모두 같은 행동 스키마를 사용한다. 연속 조작을 일반 단축키로 바꾸어 저장하지 않는다.
- 재검수 중 저장 플랜 실행기에 남은 구간당 100입력 상한을 발견해 수정했다. 새로 검증된 프로그램의 실제 입력 수를 기준으로 검사한다. 20단계 × 8구간 = 160입력 프로그램의 조건 확인·저장 재생을 가짜 화면과 장치로 검증했다. 원각이나 일반 액션의 반복 정책은 바꾸지 않았다.
- 오래된 화면과 입력 영수증은 영구 저장소로 조회할 수 있게 하면서 메모리 캐시는 최근 128개로 제한한다. 화면 600장과 관찰 노트 500개 때문에 정상 학습을 멈추지 않게 했다. 관찰 노트 역시 영구 기록 후 최근 내용만 캐시한다.
- 캐시에서 빠진 요청 ID도 DB에서 확인하므로 동일 입력이 다시 전송되지 않는다. 과거 화면은 조회할 수 있지만 현재 입력용 신선도를 되찾지 않는다.
- 장치 미지원으로 첫 구간을 전혀 보내지 못한 경우와 일부 구간 뒤 장치가 리셋된 경우를 구분한다. 후자는 불확실 입력으로 남겨 자동 재전송을 막는다.

## 실제 보드 작업

사용자가 현재 보드 사용을 승인하고 WinCro 연결을 해제했다고 답한 후에 진행했다. 앱의 모델 도구에는 업로드 기능을 추가하지 않았고, owner가 승인한 수동 CLI 작업으로만 수행했다.

- 대상: COM7, USB VID `0x2341` / PID `0x8036`, Leonardo 대상 펌웨어.
- 컴파일: Flash 12,810 / 28,672바이트, 전역 RAM 558 / 2,560바이트. 성공.
- 업로드: 사전 컴파일한 HEX를 `arduino-cli upload --verify`로 업로드. 종료 코드 0.
- 업로드 후 실제 응답: `PING -> PONG`, `GL1 -> GL1:READY`, `KQ -> OK`, `MM,0,0 -> OK`.
- KQ는 인수 없는 기능 조회이며 MM은 이동량 0이다. 실제 이동키·스킬키·클릭을 보내는 시험은 하지 않았다. 조회 후 포트를 닫았다.
- HEX SHA256: `40CD2D3FD9810930F5B8E74B84C4A2AD0E7FAEB90910344BC564870EECDDE879`.

데스크톱 제어 런타임은 `failed to write kernel assets`로 초기화에 실패했다. 초기화 재시도·리셋과 별도 Orca 경로도 확인했지만 사용할 수 없었다. UI 상태를 추정해 클릭하거나 WinCro 프로세스를 강제 종료하지 않았으며, 포트 해제는 사용자가 수행했다.

## 검수

로컬 무입력 검사: 200개 통과(30.26초). 이 중 새 무제한 실행·연속 조작 회귀 시험은 19개다. 실제 게임 입력은 아니다.

같은 200개를 한 프로세스에서 다시 검사한 결과도 통과(31.62초)했고, 기본 로깅 스레드를 제외한 새 잔존 스레드는 종료 1초 뒤 0개였다. 장기간 실게임 누수 검사를 대신하지는 않는다.

- GPT 전용 격리 시뮬레이션: 156개 통과, 실패·오류·건너뜀 0개.
- Windows UI·통신·소유 창 입력 시험: 14개 통과. 100/125/150% 화면을 아티팩트로 남겼고, 새 무제한 표시와 고정 제어 버튼 배치를 직접 확인했다. 실제 USB 보드 입력 시험은 아니다.
- 실제 Codex 0.166.0 실행기 + 실제 MCP + 가짜 로컬 모델/게임: 9개 통과. `play_control` 응답의 새 화면을 다음 요청에 바로 쓰는 경로와 연속 턴·취소·권한 격리를 확인했다. 실제 GPT의 게임 이해나 전략 능력을 검증한 것은 아니다.
- GL1 실제 펌웨어 헤더 시뮬레이션: 기간 제한·생존 확인·취소·중복·손상 패킷·시계 순환·키 누름 실패 검사 통과.

최종 전체 회귀: **2,021개 통과, 6개 건너뜀, 경고 8개, 300.37초**. 건너뜀은 명시적 활성화가 필요한 네이티브 UI·입력·Codex 모듈이며, 별도 격리 단계에서 모두 실행했다. 경고는 기존 의존성/녹화 코드의 경고로, 숨기거나 기존 녹화·인식 코드를 바꾸지 않았다.

별도 회귀 단계도 녹화 분석·저장 329개, 녹화 입력 시간 32개, 전용 동영상 인식 32개, 저장·중지·알림 식별 135개, 창 제어·특화모드 격리 431개가 통과했다. Python 3.10 + CustomTkinter 5.2.2 호환 UI 9개와 녹화 작업영역 3개도 통과했다. 시험 범위가 중복되므로 수를 합산하지 않는다.

`gpt-play-qa` 아티팩트의 XML과 UI 이미지, `recording-analysis-execution` 아티팩트의 실제 Codex/MCP 전송 결과를 다운로드해 확인했다. 실제 보드 조회·업로드 검증과 CI의 가짜 게임·장치 시험을 구분한다.

검사 범위: 구 시간·행동·시도 한도 초과 후 계속, 20회 초과 정상 모델 턴, 녹화 분석 제한 유지, 연속 조작과 새 결과 화면, 중복 요청, 구간 중 중지, 금지키·지나치게 긴 입력 거부, 펌웨어 미지원·부분 실패 구분, 캐시 삭제 후 영수증 중복 차단·과거 화면 조회, UI 배율, 실제 MCP 전송, 특화모드 격리.

## 적용 순서

1. 사용 중인 개발용 WinCro를 정상 종료하고 수정 코드로 다시 실행한다. 사용 중인 앱을 강제로 종료하거나 새 코드로 자동 재시작하지 않았다.
2. 설정에서 Arduino COM7을 다시 연결한다.
3. 화면녹화 → GPT 연결 ON → GPT 플레이에서 기존 경험과 같은 게임 창을 선택한다.
4. `새 실행으로 경험 이어하기`를 누른다. 과거 종료 세션의 시간 한도가 새 실행으로 복원되지 않는다.
5. 시작 로그의 `GL1 키 유지·동시 입력: 지원`을 확인한다. F10 개입, F11 일시정지, F12 중지는 유지된다.

## 남은 한계와 보호 범위

- 무제한은 세션 시간·행동·시도 수를 뜻한다. 한 번의 물리 입력과 새 화면 확인 사이의 시간 제한, 장치 생존 확인, 저장 용량·문서 크기 무결성 검사를 없앤 것이 아니다. 경험 저장소 약 2GB 또는 문서 저장 한도 도달 시 기존 근거를 보존하며 입력을 차단한다.
- 모델 응답 지연 자체가 사라지는 것은 아니다. 이 구현은 입력 묶음 사이에 결과를 보고 다시 판단한다. 게임 영상을 사람처럼 매 프레임 이해하는 엔진, 좌표 길찾기, 자동 사망·적 탐지는 추가하지 않았다.
- 모델이나 추론 수준을 몰래 낮추지 않았다. 개선한 것은 연속 조작과 도구 왕복 구조이며, 모델의 판단 시간 자체가 짧아졌다고 주장하지 않는다.
- 모델 서비스의 계정 사용량·접속 한도는 별개다. 이번 작업은 WinCro 내부의 세션 사용량 제한을 제거한 것이며 모델 서비스 한도를 해제하지 않는다.
- 실제 게임에서 이동 거리·스킬 반응·모델의 조작 선택·성공률·인간과 같은 반응 속도는 검증하지 못했다. 보드 지원 응답을 게임 플레이 성공으로 표시하지 않는다.
- 실제 USB 단절·프로세스 강제 종료 시 물리 키 해제 지연은 별도 측정이 필요하다. GL1의 기간 제한·생존 확인은 펌웨어 시뮬레이션으로 검사한다.
- 원각·악귀문 엔진, 기존 플랜·맵·녹화와 일반 이미지·동영상 인식 설정은 수정하지 않았다. 원각 알고리즘을 호출하거나 복사하지 않는다.
- 새 `control` 입력이 들어간 GPT 플랜은 이 스키마를 지원하는 앱 버전이 필요하다. 구형 버전 재생 호환성을 보장하지 않는다.
- 릴리즈·버전 변경·전체 업데이트는 하지 않았다. 기능 브랜치의 격리 CI만 사용했다. 작업 전부터 있던 별도 미커밋 변경은 포함하지 않았다.

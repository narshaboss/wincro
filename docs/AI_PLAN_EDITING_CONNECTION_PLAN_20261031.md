# WinCro AI 플랜 편집 연결 개발 계획

작성일: 2026-10-31. 기준 소스: 1.0.310,
`c8f780483fd6d206a2fb760e391336fae6a50840`.

## 1. 목표와 결정 요약

사용자가 자동화할 작업을 직접 수행하며 녹화하면, Codex가 영상과 실제 입력 로그를 보고 판단하여 사용자가 직접 편집한 것과 같은 형태의 플랜을 제작한다. WinCro 내부에 별도 판단 AI를 넣거나, 재생 중 매 액션을 AI에 물어보는 구조로 만들지 않는다.

| 항목 | 설계 기준 |
| --- | --- |
| 판단 담당 | 현재 대화에서 작업하는 Codex가 작업 의미와 편집안을 판단한다. |
| WinCro 담당 | 녹화 자료 제공, 허용된 편집 적용, 저장 검증, 승인된 테스트 결과 제공을 담당한다. |
| 연결 | 로컬 MCP 서버와 WinCro 편집 어댑터를 연결한다. |
| 기본 작업 대상 | 원본을 복사한 AI 초안이다. 원본과 재생목록은 자동 변경하지 않는다. |
| 첫 완성 범위 | 녹화 읽기, 스샷 추출, 일반 액션 편집, 초안 검수, 새 플랜으로 등록이다. |
| 실제 실행 | 기본 차단한다. 별도로 지정하고 승인한 격리 Windows에서만 허용한다. |
| 기존 플랜 교체 | 새 플랜 등록과 다른 권한으로 취급하며 초기 구현에서는 제공하지 않는다. |
| 특화모드 | 두 엔진, 프로필, 맵과 특화 설정을 수정하지 않는다. |
| 이번 작업 | 개발 계획 문서만 작성한다. 구현, MCP 등록, 앱 조작, 버전 배포는 하지 않는다. |

최우선 합격 조건은 생성 속도가 아니라 **원본 보존, 정확한 저장, 사용자 편집과의 충돌 방지, 승인 없는 입력 차단**이다.

## 2. 실제 사용 흐름

1. 사용자가 만들고 싶은 작업과 종료 조건을 짧게 설명하고, WinCro로 작업을 녹화한다. 입력 로그도 함께 보관한다.
2. 사용자가 해당 녹화와 참고 플랜을 선택하고 AI 편집 연결을 켠다. 연결은 기본 OFF다.
3. Codex가 작업 단계, 클릭 대상, 키 입력, 전후 화면을 확인한다. 기존 플랜은 제작 방식의 참고 자료이며 임의 변경 대상이 아니다.
4. Codex가 독립 초안에 상위·하위 액션, 스샷, 검색 범위, 대기시간, 반복 설정을 추가한다.
5. 근거가 부족한 반복 종료, 예외 상황, 위험 작업만 사용자에게 확인한다. 추측을 확정 설정으로 숨기지 않는다.
6. WinCro가 초안의 액션 트리와 변경 사항, 이미지, 영상 시점을 표시한다. 사용자는 일부 설정을 직접 수정할 수 있다.
7. 영상 기반 인식 대조와 구조·저장 검사를 수행한다. 실동작 검사가 필요한 경우 별도 승인한 격리 환경에서 수행한다.
8. 사용자가 승인하면 새 플랜으로 등록한다. 기존 플랜 교체, 재생목록 편입, 자동 실행, 전체 업데이트는 자동으로 하지 않는다.

원본 플랜을 고치고 싶을 때도 첫 버전은 원본을 복사해 개선본을 만드는 방식이다. 원본 교체는 후속 단계에서 별도 설계한다.

## 3. 현재 코드에서 확인한 연결부

| 현재 구조 | 연결 설계에 미치는 영향 |
| --- | --- |
| `tools/parsec_mcp_server.py`에 로컬 STDIO MCP가 있다. | 기존 Parsec 연결은 보존하고, 플랜 편집 서버를 별도 추가한다. 기존 코드가 플랜 편집을 제공하는 것은 아니다. |
| `src/analyzer/video_analyzer.py`는 입력 로그 기반 변환기다. | 기존 분석을 AI 판단 기능으로 오인하지 않는다. 현재 고정 크롭과 단순 대기 계산은 그대로 AI 제작 품질을 보장하지 못한다. |
| `PlanDetailDialog`가 메모리 플랜과 수정 상태를 가진다. | 디스크 JSON만 바꾸면 열린 에디터가 이전 내용으로 덮어쓸 수 있다. |
| `PlanDetailDialog._save_plan`은 `PLANS_DIR`에 저장한다. | 이 메서드를 초안 저장에 그대로 재사용하면 정식 플랜 폴더에 기록될 수 있다. |
| 일반 부분실행은 수정본을 자동 저장하고 선택 지점 이후를 실행한다. | MCP의 '한 액션 테스트'에 기존 버튼 콜백을 그대로 연결하면 안 된다. |
| 부분실행의 점프가 원본 전체 규칙을 참조할 수 있다. | 승인한 액션만 보았다고 해서 실제 실행 범위도 그 안에 머무르는 것은 아니다. |
| `dump_json_file`에 임시 파일, flush/fsync, 원자적 교체와 재읽기가 있다. | 단일 JSON 저장에 재사용한다. 이미지 여러 개와 JSON, DB까지 하나의 원자적 거래가 되는 것은 아니다. |
| `AutomationPlan.to_dict`는 액션 ID를 검증한다. | 기존 검증을 재사용하되, 부모·점프·호출·모니터링 등 참조 검증은 추가로 필요하다. |
| 플랜 JSON이 기준이고 녹화 DB 연결은 보조 정보다. | 파일 저장과 녹화 이름·연결 DB 동기화의 성공을 구분해서 보고한다. |
| 개발판과 배포판의 데이터 경로가 다르다. | 작업 디렉터리만 보고 앱·데이터 위치를 추정하지 않는다. 실제 연결 인스턴스가 보고한 경로에 묶는다. |

현재 자동사냥 저장 트리는 상위 14개, 전체 213개 액션이다. 연마석공장은 일반 트리 47개 액션과 자동목록 등록 9종, 제작·추출·복귀 사이클을 가진다. 모니터링 전용 액션은 일반 트리와 별도의 중첩 구조이므로 읽기 모델에서 빠뜨리지 않아야 한다. 이 수치는 기준 소스의 저장 상태이며 향후 바뀔 수 있다.

## 4. 연결 구성

```text
사용자 지시와 승인
        |
Codex: 영상 이해와 편집 판단
        |
로컬 MCP 서버: 허용된 명령만 전달
        |
Windows 로컬 통신: 인스턴스 식별과 세션 인증
        |
WinCro AI 편집 서비스
        +-- 독립 초안 저장소와 변경 거래
        +-- 영상 프레임·입력 로그 제공 작업자
        +-- UI 어댑터: 초안 표시와 사용자 수정 동기화
        +-- 검증 작업자: 구조·인식·저장 대조
        +-- 테스트 어댑터: 별도 승인된 격리 인스턴스만

기존 플랜 / 재생목록 / 실행 엔진 / 특화모드 / 맵
        기본 읽기 전용, AI 초안 서비스와 분리
```

Codex와 MCP 서버는 STDIO로 연결한다. 앱 내부 통신은 Windows named pipe를 우선 검토하되, 보안·패키징 실험을 통과한 뒤 규격을 확정한다. 인터넷 공개 서버나 공개 수신 포트는 필요하지 않다. 로컬 MCP 지원과 등록 방식은 [공식 OpenAI 문서](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)에 따른다.

WinCro가 꺼져 있으면 서버는 연결 오류를 반환한다. 도구 호출이 앱을 몰래 실행하거나, 임의의 다른 WinCro에 연결되거나, 종료된 세션을 자동 복원하지 않는다. 원격 PC 연결과 Parsec 제어는 이번 연결 범위에 포함하지 않는다.

MCP 서버는 앱 소유의 쓰기 서비스를 호출할 뿐 정식 JSON이나 DB에 독자적으로 기록하지 않는다. 녹화 디코딩과 저장 작업은 작업자에서 수행하며, Tk 위젯 접근과 UI 상태 반영만 메인 스레드에서 처리한다. 메인 스레드는 작업자 완료를 기다리며 잠그지 않는다.

연결 프로토콜 버전은 앱 표시 버전과 따로 관리한다. 최초 연결에서 지원 도구·스키마·권한을 교환하고 호환되지 않는 쓰기는 거부한다. 현재 310에 아직 없는 연결을 지원한다고 가정하지 않으며, 기존 Parsec MCP 설정을 교체하지 않는다.

## 5. 권한과 데이터 소유권

| 권한 | 허용 내용 | 기본 정책 |
| --- | --- | --- |
| 자료 읽기 | 사용자가 지정한 플랜, 녹화, 입력 로그를 읽는다. | 선택된 자료로 제한한다. |
| 초안 편집 | 독립 초안에 액션과 미디어를 추가·수정한다. | 원본 기록과 실제 입력을 허용하지 않는다. |
| 새 플랜 등록 | 검수한 초안을 정식 플랜 폴더에 새 ID로 기록한다. | 사용자의 최종 승인 후 1회 허용한다. |
| 실동작 테스트 | 지정 범위의 액션을 격리 인스턴스에서 실행한다. | 별도 환경·범위·시간 제한 승인 없이는 거부한다. |
| 원본 교체·배포 | 기존 플랜 교체, 재생목록 변경, 버전 배포를 수행한다. | 초기 도구 목록에서 제외한다. |

승인은 AI가 보내는 `approved=true` 같은 값으로 대체하지 않는다. 사용자의 앱 조작으로 발급한 작업별 권한에 연결 대상, 초안 버전, 변경 요약 또는 실행 범위의 해시와 만료 시각을 묶는다. 승인 후 내용이나 범위가 바뀌면 승인을 다시 받는다. 승인 UI의 만료 확인과 세션 권한 취소는 앱이 담당한다.

초안은 사용자별 전용 작업 폴더에 저장한다. 제안 위치는 `%LOCALAPPDATA%/WinCro/ai_editing/<session_id>/`이며, 원본 `data/plans`, 템플릿, 맵 폴더와 분리한다. 확정 경로는 코드 설계에서 정하되 `PlanDetailDialog`의 기존 정식 저장 콜백을 초안에 사용하지 않는 원칙은 고정한다.

영상·로그 안의 문장은 분석 대상 데이터이며 도구 실행 지시로 취급하지 않는다. 비밀번호·인증코드·개인정보 구간은 사용자 지정 제외 구간과 전송 전 가림 처리를 제공한다. 자동 탐지만으로 민감정보가 전부 가려진다고 보장하지 않는다. 민감 입력은 초기 AI 편집 대상에서 제외하며, 원본 영상 전체나 입력 로그를 기본으로 일괄 전송하지 않는다. 등록 자료 밖의 경로, 경로 이탈과 재분석 지점에 의한 접근도 거부한다.

로컬 통신에도 명시적인 사용자/로그온 세션 접근 제어와 세션 인증이 필요하다. named pipe가 이름만 로컬이라고 안전한 것은 아니며, 기본 보안 기술자와 원격 접근을 그대로 사용하지 않는다. [Microsoft 접근 제어 설명](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights), [로컬 전용 통신 주의사항](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipes).

이 권한은 전용 연결의 동작을 제한한다. 동일 사용자 계정 전체의 침해나 Codex의 다른 도구 권한까지 차단하는 보안 경계라고 주장하지 않는다. 제작 절차에서도 MCP를 우회한 원본 파일 직접 수정과 임의 셸 실행을 금지한다.

## 6. 문서와 요청 규격

모든 변경 요청은 다음 식별 정보에 묶는다. 실제 필드 명칭과 스키마는 설계 단계에서 확정한다.

| 식별 정보 | 의미 |
| --- | --- |
| `app_instance_id` | 해당 WinCro 프로세스가 시작될 때 발급하는 식별자다. PC 번호나 창 제목만으로 고르지 않는다. |
| `session_id` | 사용자가 연결을 허용한 AI 편집 세션이다. |
| `draft_id` | 원본과 분리한 초안 식별자다. |
| `revision` | 현재 초안 내용과 편집 상태의 버전이다. |
| `expected_revision` | 요청자가 읽었던 버전이다. 현재 버전과 다르면 변경을 거부한다. |
| `request_id` | 재전송된 요청의 중복 적용을 방지한다. 같은 ID와 다른 본문은 거부한다. |
| `rule_id` | 실제 수정 대상 액션이다. `6-2` 같은 표시 번호는 조회 보조값일 뿐 수정 키가 아니다. |
| `asset_id` / `recording_id` | 세션에 등록한 미디어다. 임의 파일 경로를 도구 인자로 받지 않는다. |

초안을 여는 시점에 원본 파일 해시와, 열린 에디터에서 복사한 경우 에디터 스냅샷의 해시를 함께 보관한다. 디스크 저장본과 저장 전 편집본 중 어느 쪽을 참고했는지 명시한다. 저장 전 설정 팝업이나 텍스트 입력이 스냅샷에 안전하게 반영되지 않으면 `EDITOR_BUSY`로 거부하고 먼저 사용자 확인을 받는다. 팝업을 강제로 닫거나 저장하지 않는다.

사용자와 Codex의 초안 변경은 같은 편집 서비스를 통해 순서대로 처리한다. 사용자 수정도 revision을 올린다. 원본 또는 참고한 편집 상태가 바뀌면 기존 스냅샷을 조용히 최신으로 덮어 바꾸지 않고 변경을 표시한다. 새 플랜 등록 전 차이를 다시 확인한다. 버전 검사와 변경 적용 사이에 다른 쓰기가 끼어들 수 없도록 한 작성자 경로에서 처리한다.

초안 모델은 원본의 액션 리스트, 자식, 모니터링 및 자동목록 설정과 가변 객체 참조를 공유하지 않는다. 플랜 복제 시 액션 ID를 유지하더라도 초안/플랜 ID로 소유권을 구분하며, 같은 표시 이름의 다른 플랜이나 다른 세션을 수정하지 않는다.

반환값은 적어도 성공 여부, 오류 코드, 적용 후 revision, 변경된 액션 ID, 저장 상태를 포함한다. 긴 작업은 즉시 `job_id`를 반환하고 상태 조회/취소로 추적한다. HTTP 또는 MCP 요청의 대기 시간 만료를 작업 실패나 취소 완료로 간주하지 않는다.

대표 오류는 `APP_NOT_CONNECTED`, `WRONG_INSTANCE`, `EDITOR_BUSY`, `REVISION_CONFLICT`, `UNSUPPORTED_SCHEMA`, `INVALID_REFERENCE`, `MEDIA_NOT_READY`, `PERMISSION_REQUIRED`, `TEST_SCOPE_VIOLATION`, `SAVE_FAILED`, `SAVE_STATE_UNKNOWN`, `CANCEL_PENDING`으로 구분한다. 원본으로 우회하거나 인식률을 낮춰 성공으로 바꾸지 않는다.

## 7. 제공할 MCP 도구

아래는 구현 예정 도구의 논리 목록이다. 현재 사용 가능한 도구라는 뜻이 아니다.

| 도구 | 역할과 제한 |
| --- | --- |
| `connection_status` | 앱 버전, 연결 인스턴스, 제공 기능과 권한을 확인한다. 앱을 시작하거나 전면으로 가져오지 않는다. |
| `list_plans` / `read_plan` | 허용된 플랜의 전체 트리와 설정을 읽는다. 긴 트리는 페이지별로 읽어도 부모·ID·참조가 보존되어야 한다. |
| `read_recording` | 영상 정보, 입력 로그 유무, 녹화 영역과 시간 연결 상태를 읽는다. |
| `get_frames` / `get_input_events` | 지정한 시간 구간의 장면과 입력을 제한된 분량으로 제공한다. |
| `open_draft` | 지정 원본 또는 빈 플랜으로 독립 초안을 만든다. 기존 데이터에 ID를 덮어쓰지 않는다. |
| `create_asset_crop` | 원본 영상의 특정 장면과 사각형으로 무손실 PNG를 만든다. 출처를 보관한다. |
| `stage_edits` | 액션 추가·수정·이동·복제·삭제를 거래 단위로 제안하고 검증한다. 중간 실패 시 일부만 적용하지 않는다. |
| `read_draft` / `preview_changes` | 현재 초안과 이전 버전 대비 변경을 조회한다. |
| `validate_draft` | 구조, 참조, 이미지 범위, 영상 대조와 저장 준비 상태를 검사한다. 실제 입력은 보내지 않는다. |
| `save_draft` | 초안 저장소에 실제 저장하고 다시 읽어 검증한다. 정식 등록과 구분한다. |
| `publish_new_plan` | 승인된 revision만 새 플랜으로 등록한다. 원본 덮어쓰기와 자동 재생목록 편입을 허용하지 않는다. |
| `close_session` | 세션 권한을 해제한다. 초안 삭제를 기본 동작으로 삼지 않는다. |
| `get_job` / `cancel_job` | 장시간 분석·저장·검증 작업의 상태를 확인하고 취소한다. |
| `prepare_test` / `run_test` | 후속 실행 단계에서만 제공한다. 승인한 격리 환경과 확정 실행 범위에 제한한다. |
| `stop_test` / `read_test_result` | 해당 테스트만 중지하거나 결과를 읽는다. 다른 재생을 중단하지 않는다. |

편집 필드에는 액션 종류, 설명, 대상 이미지, 클릭·키 입력, 대기·랜덤·반복, 검색 범위, 상하위 관계를 포함한다. 초기 수정 허용 범위는 일반 액션이다. 모니터링·자동목록은 읽기와 원형 보존을 먼저 보장하고, 전용 스키마와 검수가 준비된 단계에서 편집을 연다. 특화모드와 맵은 끝까지 이번 편집 허용 목록에서 제외한다.

순서 이동은 액션 ID와 부모 ID, 기준 액션의 앞/뒤로 표현한다. 부모를 자식 아래로 옮기는 순환, 중복 ID, 잘못된 부모 포인터와 끊어진 점프·호출 참조는 거부한다. 참조가 걸린 액션 삭제는 연결된 변경을 함께 명시해야 하며 임의로 다른 액션을 대상으로 고치지 않는다.

## 8. 원본 보존과 저장 거래

기존 데이터는 복사한 원시 JSON으로 보존하고, 지원 모델로 변환·직렬화했을 때 정보가 빠지는지 먼저 검사한다. 알 수 없는 필드를 조용히 삭제하거나 기본값으로 덮지 않는다. 손실 없이 보존·표시할 수 없는 스키마는 수정하지 않고 거부한다. 특화 설정은 해석해서 다시 만들지 않고 보호된 원형 데이터로 유지한다.

초안 저장과 새 플랜 등록은 각각 다음 절차를 따른다.

1. 요청 ID, 세션 권한, 대상 인스턴스, 예상 revision과 저장 경로를 검사한다.
2. 현재 초안 전체를 복사해 후보를 만들고, 요청한 변경 이외의 차이가 없는지 비교한다.
3. ID·부모·참조·설정 범위·미디어 존재·미해결 조건을 검증한다.
4. 새 이미지를 임시 영역에 먼저 기록하고 실제 디코딩과 해시를 확인한다. 기존 이미지를 덮어쓰지 않는다.
5. 복구 기록을 남기고 검증된 새 자산을 고유 이름으로 확정한다. 이미지가 준비된 뒤에만 이를 참조하는 JSON을 교체한다.
6. `dump_json_file`의 단일 파일 저장 방식으로 후보 JSON을 기록한다. 새 정식 플랜 ID는 UUID 기반으로 만들고, 목적지와 같은 볼륨에서 준비한 후보를 기존 파일을 교체하지 않는 확정 연산으로 등록한다. 존재 여부를 먼저 확인한 뒤 `os.replace`로 덮는 방식은 동시 생성 경쟁을 막지 못하므로 새 플랜 등록에는 사용하지 않는다. 세부 확정 연산은 Windows 실패 주입 실험으로 검증한다.
7. 실제 JSON과 자산을 다시 읽는다. 의도한 설정·순서·상하위·참조와 동일한지, 실행 모델로 로드 가능한지 확인한다. 직렬화에서 추가된 기본값도 허용 목록 없이 무시하지 않는다.
8. 필요한 녹화 DB 연결은 별도로 검사한다. JSON 저장과 DB 보조 정보 동기화 상태를 각각 반환한다.
9. 저장 결과, revision과 자산 목록이 포함된 영수증을 남기고 UI에 확정 상태를 반영한다.

여러 파일에 완전한 원자성을 보장한다고 주장하지 않는다. JSON보다 이미지를 먼저 확정해 깨진 참조를 피하고, 실패 시 참조되지 않은 새 자산이 남을 수 있다는 형태로 복구한다. 정리 대상은 해당 작업이 만든 파일로 제한하며, 기존 공유 이미지나 원본 폴더 전체를 정리하지 않는다.

쓰기 직후 검증 실패나 연결 끊김으로 결과가 불분명하면 `SAVE_STATE_UNKNOWN`을 반환한다. 즉시 같은 변경을 재실행하지 않고 요청 영수증과 실제 파일을 확인해 상태를 복구한다. 같은 요청 ID 재전송은 동일 결과를 반환해야 하며 액션이나 플랜을 두 번 추가해서는 안 된다. 커밋 경계의 취소는 완료를 확인한 뒤 결과를 알려주고, 성공한 저장을 취소된 것처럼 표시하지 않는다.

앱 종료·충돌 후 복구는 자동 원본 교체가 아니라 초안 복원과 기록 대조다. 등록이 완료된 새 플랜은 사용자 확인 없이 삭제하지 않는다. 기존 참고 플랜 변경이나 DB 보조 동기화 실패를 숨기지 않는다.

## 9. 녹화 자료와 AI 편집 절차

### 녹화 기초 자료

클릭·키 입력은 실제 이벤트 로그를 기준으로 하고, 영상은 대상과 화면 전환을 이해하는 근거로 쓴다. 입력 시각은 녹화 프레임과 같은 단조 시계에 맞추는 방향으로 설계한다. 프레임별 실제 시각, 일시정지 구간, 누락 프레임, 녹화 원점·해상도·DPI 정보를 세션 명세에 보관한다. 화면 좌표와 영상 좌표를 혼용하지 않는다.

현재 녹화에는 모든 정보가 없으므로 새 녹화와 기존 자료를 구분한다. 기존 녹화는 보정 가능 여부와 오차를 표시하고, 시간 연결이 불확실한 장면을 확정 캡처로 채택하지 않는다. 전체 영상 길이 비율 하나로 중간 일시정지나 불규칙 프레임 누락까지 해결된 것으로 보지 않는다.

새 기록 방식은 기존 녹화·재생 기본 동작을 바꾸지 않는 부가 정보부터 검토한다. 캡처 루프가 파일 쓰기나 AI 요청을 기다리지 않게 하고, 기록 부하와 자원 제한을 검증한다. 이 변경은 MCP 연결 자체와 별도 커밋·회귀 대상으로 관리한다.

### AI가 수행할 판단

- 먼저 기존 플랜의 제작 패턴을 요약한다. 로그인, 창 제어, 선택·입력·확인, 반복·복귀 같은 예시를 필요한 부분만 참고하며, 플랜 이름으로 실행 동작을 선택하지 않는다.
- 영상 전체를 매번 보내지 않고 입력 시점 주변과 전환 장면을 추린다. 짧은 팝업을 놓치지 않도록 클릭 전후 구간은 촘촘히 확인한다.
- 클릭 전의 실제 원본 프레임에서 안정된 버튼·글자 부분을 자른다. 커서, 눌림 효과, 변하는 숫자와 주변 배경을 가급적 제외한다. 이미지 생성으로 템플릿을 다시 그리지 않으며 마스크를 자동 생성하지 않는다.
- 반복되는 이미지라도 대상 창과 범위를 나눈다. 해상도나 창 위치가 달라지는 PC의 인식 성공까지 단일 녹화로 보장하지 않는다.
- 입력 간격, 화면 변화와 안정 시점을 근거로 대기를 제안한다. 한 번의 녹화에서 실제 로딩과 사용자 고민 시간을 확정하기 어려우면 확인 필요로 표시한다. 기존 일반 대기·이미지 조건으로 표현할 수 없는 동작을 지원하는 척하지 않는다.
- 반복 입력이 업무 반복인지 실패 재시도인지 구분한다. 종료 조건과 건너뛰기·복귀는 사용자 지시나 녹화 근거가 있을 때만 확정한다.
- 캡처 후보를 등장 장면뿐 아니라 다른 시점·다른 창·비슷한 버튼과 대조한다. 검사 부족을 낮은 인식률로 덮지 않는다. 309/310 인식 기준과 전용 동영상 격리를 유지한다.
- 각 액션의 근거로 영상 시점, 이벤트 구간, 자산 ID와 미해결 질문을 남긴다. 이 정보는 실행 플랜의 새 필드가 아니라 별도 초안 메타데이터에 보관한다.

AI 판단 절차는 버전 관리하는 제작 지침으로 제공한다. WinCro가 의미를 추론하는 기능과 혼합하지 않되, 범위·권한·형식·참조 검증은 WinCro가 기계적으로 수행해야 한다. AI의 판단만으로 저장 무결성과 안전을 대체하지 않는다.

## 10. UI와 동시 편집

설정에 `AI 편집 연결`을 기본 OFF로 추가하고, 연결된 인스턴스와 세션을 확인하게 한다. 인증 자료는 화면·로그·배포 파일에 노출하지 않는다. 연결 해제는 언제든 가능하며, 진행 중 작업의 저장 여부를 별도로 표시한다.

초안 검토 화면은 기존 WinCro 테마, 글꼴과 행 간격을 사용한다. 액션 트리, 선택 액션 설정, 원본 장면/캡처 미리보기, 확인 필요 항목을 보여준다. 하단 동작은 `초안 저장`, `새 플랜으로 등록`, `닫기`로 구분한다. 초안 저장과 정식 등록을 모두 모호한 '저장' 하나로 부르지 않는다. 닫을 때 저장 전 내용이 있으면 초안 보관 여부를 확인한다.

기존 상세 편집창을 그대로 상속하거나 버튼 콜백을 호출해 초안 화면을 만드는 방식은 금지한다. 정식 저장 경로와 부분실행 자동 저장이 섞일 수 있기 때문이다. 초안 전용 모델·저장 서비스를 두고 안전하게 분리한 표시 컴포넌트만 재사용한다. 정상 편집창의 저장 경로를 전면 개편하는 작업도 이번 연결에 묶지 않는다.

AI 변경은 여러 필드를 한 묶음으로 검증한 뒤 해당 행과 관련 참조 표시만 갱신한다. 숫자 입력·대기 수정·순서 이동마다 전체 목록을 다시 만들지 않는다. 접기·펼치기, 선택, 스크롤 상태를 유지한다. 사용자 수정이 들어오면 AI의 이전 revision 요청은 충돌로 거부하며 자동 병합하지 않는다.

작은 화면과 100/125/150% 배율에서 목록·버튼·설정이 잘리지 않아야 한다. 구체적인 화면 배치는 별도 설계 시 캡처 검수한다. 지금 계획만으로 UI 품질 검수를 통과했다고 보고하지 않는다.

## 11. 실제 실행과 중지 경계

초기 읽기·편집 버전에는 실제 실행 도구를 활성화하지 않는다. 오프라인 검증과 실제 클릭·키입력을 다른 상태로 표시한다.

실행 도구를 추가할 때는 지정한 격리 Windows에 앱과 데이터 복사본을 두고, 인스턴스·데이터 루트·장치·승인 범위를 다시 확인한다. 첫 검수에서는 가짜 대상 창과 모의 입력을 사용한다. 실제 게임과 Arduino 검수는 추가 승인과 테스트 장치가 있을 때만 수행한다. 메인 PC의 전역 입력, 후킹과 실행 중 재생을 실험 대상으로 삼지 않는다.

실행 전에는 선택한 액션뿐 아니라 자식, 반복 부모, 자동목록 문맥, 점프·호출의 도달 범위를 계산해 실행 명세를 만든다. 범위 밖 참조나 모니터링 점프, 특화모드로 넘어갈 가능성이 있으면 초기 실행 버전에서는 거부한다. 원본 전체 플랜을 숨겨서 참조하는 부분실행으로 우회하지 않는다. 기본 일반 액션 테스트부터 검증한 뒤 복잡한 문맥을 단계적으로 지원한다.

기존 실행기를 우회하는 세 번째 실행 엔진을 만들지 않는다. 지원하는 테스트 범위만 기존 실행 진입점에 위임하고, 공통 입력·중지·일시정지 계약을 따른다. 특화모드를 직접 `RuleExecutor`로 실행하는 도구는 제공하지 않는다.

테스트 실행에는 단계·시간 상한과 세대 식별자를 둔다. 설계 초기값 제안은 30단계/120초이며, 동작별 정의와 실제 지연을 확인해 확정한다. 이 상한은 테스트에만 적용하고 기존 플랜의 반복·무한대기 설정을 변경하지 않는다. 승인한 테스트가 끝나거나 연결이 끊기면 새 입력을 허용하지 않고 중지를 요청하며, 입력 해제 완료까지 확인한다. 이전 세대 콜백이 새 실행을 이어가지 못하게 한다. 시간 만료만으로 중지 완료라고 보고하지 않는다.

전체 앱 종료, 다른 플랜 중지, 재부팅, 자동 업데이트, Parsec 접속은 전용 편집 도구에서 허용하지 않는다.

## 12. 예상 파일 구성

아래 경로는 새로 만들 모듈의 책임 구분 제안이다. 기존 파일이라는 뜻은 아니다.

| 제안 경로 | 책임 |
| --- | --- |
| `tools/wincro_mcp_server.py` | MCP 도구와 앱 통신을 연결하는 얇은 서버다. 기존 Parsec 서버와 분리한다. |
| `src/agent_bridge/contracts.py` | 도구 입력·응답, 버전, 오류, 권한과 상태 규격을 정의한다. |
| `src/agent_bridge/session.py` | 인스턴스 식별, 세션, 승인 범위와 요청 중복 처리를 관리한다. |
| `src/agent_bridge/transport.py` | 접근 제어된 로컬 통신과 종료 처리를 담당한다. |
| `src/agent_bridge/drafts.py` | 초안 상태, revision, 원본 보존과 편집 거래를 담당한다. |
| `src/agent_bridge/storage.py` | 자산 확정, JSON 저장, 영수증과 충돌 복구를 담당한다. |
| `src/agent_bridge/media.py` | 제한된 프레임·입력 구간과 크롭 자산을 제공한다. |
| `src/agent_bridge/validation.py` | 구조·참조·범위·왕복 저장 검증을 담당한다. |
| `src/ui/ai_draft_editor.py` | 초안 검토와 사용자 수정 화면이다. 정상 상세 편집창과 저장 경로를 분리한다. |
| `src/agent_bridge/app_adapter.py` | 앱 시작·종료, 메인 스레드 스냅샷과 UI 전달만 연결한다. |
| `src/agent_bridge/test_adapter.py` | 후속 승인 단계의 격리 테스트만 연결한다. |
| `tests/test_ai_bridge_*.py` | 프로토콜·권한·충돌·저장·미디어·UI·중지 회귀를 분리한다. |
| `docs/AI_PLAN_EDITING_OPERATOR.md` | 후속 에이전트가 따를 제작 절차와 금지 경계를 기록한다. |

OFF 상태에서는 서버·작업자·무거운 분석 의존성을 시작하지 않는다. 큐, 프레임 캐시, 작업 기록과 연결 수는 상한을 두며 실제 녹화·재생 성능 대조로 정한다. MCP 라이브러리는 기존 Parsec 환경을 바꾸지 않도록 분리하고, 호환 버전은 격리 CI에서 확정한다. 큰 공용 UI 파일의 무관한 정리와 리팩터링은 함께 진행하지 않는다.

## 13. 구현 순서와 완료 기준

| 단계 | 개발 내용 | 다음 단계 진입 조건 |
| --- | --- | --- |
| 0. 기준 고정 | 기존 플랜·자산·맵 해시와 원본 사본, 프로토콜·쓰기 경계를 확정한다. | 변경 금지 영역과 테스트 자료가 고정된다. |
| 1. 읽기 연결 | 인스턴스 식별, 권한, 플랜·녹화·입력 조회와 시간/좌표 명세를 만든다. | 잘못된 앱 연결·범위 밖 읽기를 거부하고 원본이 바뀌지 않는다. |
| 2. 초안 편집 | 복제, 일반 액션 CRUD·순서·상하위·필드 편집, 크롭과 거래를 만든다. | 충돌·중복 요청·취소·알 수 없는 필드 보존 검사가 통과한다. |
| 3. 검토와 저장 | 초안 UI, 실제 저장 재읽기, 새 플랜 등록과 복구를 연결한다. | 사용자 편집 손실과 원본 덮어쓰기 없이 재시작 후 동일하게 로드된다. |
| 4. 제작 실험 | 짧은 녹화로 Codex가 실제 초안을 만들고 영상 대조·사용자 평가를 수행한다. | 필요한 스샷·키·범위·대기와 묶음이 근거와 함께 재현된다. |
| 5. 제한 실행 | 승인된 격리 환경과 일반 액션 테스트 도구를 연결한다. | 실행 범위 이탈·중지·해제·낡은 콜백 검사가 통과한다. |
| 6. 복잡한 구성 | 모니터링·자동목록 편집과 테스트를 전용 계약으로 확장한다. | 컨텍스트와 점프 범위 검수가 완료된다. 특화모드 변경은 계속 제외한다. |

1차 사용 가능한 결과물은 단계 0~4다. '영상으로 초안을 제작하고 새 플랜으로 저장'까지 실제로 확인해야 완료다. 단계 5와 6을 구현하지 않은 상태에서 자동 실동작 검수까지 완성됐다고 보고하지 않는다. 원본 교체와 무인 운영은 별도 후속 과제다.

| UI | 100/125/150% 배율, 작은 화면, 긴 이름, 긴 트리, 접기·스크롤 보존, 반복 수정 시 전체 재생성 여부를 검사한다. |

실행 검사는 격리 Windows에서만 수행한다. `tests/test_special_mode_engine_isolation.py`와 전체 회귀를 필수 게이트로 둔다. 동영상 인식은 `docs/VIDEO_RECOGNITION_BASELINE.md`의 경계를 유지한다. 계획 작성 시점에는 이 새 연결의 테스트를 실행하거나 통과한 상태가 아니다.

첫 제작 실험은 1~2분의 짧은 작업으로 시작한다. 창 열기, 이미지 클릭, 값 입력, 확인, 대기처럼 결과를 대조할 수 있는 작업을 선택한다. 반복 종료·분해 같은 작업은 조건을 명시한 다음 추가한다. 생성 비율이나 시간 절감률은 이 실험 전에는 수치로 약속하지 않는다.

## 15. 설계 착수 시 확정할 산출물

첫 설계 작업은 도구 스키마·권한표, 초안 상태 전이, 저장 실패별 복구 표, 로컬 통신 보안 실험, UI 와이어프레임, 골든 플랜/녹화 테스트 자료를 산출한다. 그 뒤 읽기 전용 수직 흐름 하나를 먼저 구현한다. 시작부터 모든 액션과 원본 덮어쓰기를 한꺼번에 개방하지 않는다.

초안 상태는 `읽기 → 편집 → 검증 → 초안 저장 → 등록 승인 → 새 플랜 등록`으로 구분한다. 사용자 편집 시 기존 검증/승인은 무효가 된다. '파일이 저장됨', '구조가 유효함', '영상에서 인식됨', '실동작 성공'은 서로 다른 결과이며 하나로 뭉쳐 성공으로 표시하지 않는다.

구조적 리스크는 특히 에디터/디스크 상태 불일치, 기존 부분실행 재사용, 다중 파일 저장의 중간 실패다. 이 세 경계를 통과하지 못하면 AI가 플랜을 잘 설명하거나 MCP 통신이 된다는 이유만으로 기능을 완성 처리하지 않는다.

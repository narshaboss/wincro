# 사용자 플랜에서 확인한 AI 제작 기준

2026-10-31 저장된 `자동사냥`과 `레이드공장`을 읽고 정리한 참고 기준이다. 원본 플랜과 실행 설정은 수정하지 않았다. 아래 '확인'은 저장된 설정에 대한 사실이며, 작업 목적에 대한 해석은 이름과 구조를 바탕으로 한 추론이다. 실제 녹화나 플레이 성공 검증으로 대체하지 않는다.

## 자동사냥의 작업 구성

원본: `data/plans/plan_20260118_174859.json`. 상위 14개, 일반 액션 트리 전체 213개다. 모니터링 전용 액션은 이 트리와 별개로 중첩되어 있다.

큰 흐름은 VPN 실행, 홈페이지 접속, 로그인, 두 클라이언트 배치, 캐릭터 접속, 사냥 준비/시작, 결과 처리, 남은 작업과 마무리로 구성된다. 사용자는 개별 클릭 하나를 상위 작업으로 만드는 것이 아니라, 작업 목적별로 묶고 필요한 조작을 하위에 배치한다.

| 확인한 설정 | 제작 시 참고할 의미 |
| --- | --- |
| 1번은 VPN 클릭 후 15초 대기와 스킵을 사용한다. | 시작 준비 단계와 필수 여부를 분리한다. 15초가 모든 PC의 최적 시간이라는 뜻은 아니다. |
| 홈페이지 단계에는 창 제어, F6, 주소 입력과 ENTER가 연결된다. | 아이콘 클릭만 복사하지 말고 창 상태와 다음 화면 진입까지 하나의 작업으로 이해한다. |
| 왼쪽은 `[0,0,827,795]`, 오른쪽은 `[897,1,1715,795]` 같은 별도 범위를 사용한다. | 같은 이미지라도 대상 창을 구분한다. 새 녹화에서는 이 좌표를 그대로 복사하지 않고 실제 배치로 다시 정한다. |
| 6-2는 '문파요강+복숭아 받기'이며 하위 8개 동작을 가진다. | 목록 진입, 항목 선택, 확인과 정리를 한 작업으로 묶는다. |
| 6-2-2와 6-2-5는 같은 이미지지만 검색 영역이 다르다. | 같은 버튼 모양으로 서로 다른 항목을 다룰 때 템플릿 이름만 보고 합치지 않는다. |
| 6-2-3과 6-2-6은 트리거 미감지 복귀 대상을 `rule_41a59d7d`, 현재 6-2로 지정한다. | 단순 '이전 클릭'이 아니라 해당 작업의 시작점으로 복귀하는 구성을 참고한다. |
| 복귀 전 키는 ESC, TAB, ENTER, ESC 순서이며 키별 반복과 대기가 다르다. | 복구 준비 조작은 순서와 키별 설정을 함께 보존한다. 새 작업에서 이 조합이 필요한지는 별도로 판단한다. |
| ENTER 4회 입력의 반복 간격은 1.1초 또는 1.2초이고, 액션 후 대기는 0.9초다. | 키를 누르는 간격과 입력 묶음이 끝난 뒤 대기를 혼동하지 않는다. |

8번 모니터링에는 감시 묶음 5개가 있다. 첫 묶음은 감시 이미지 6종과 동영상클릭·ENTER 입력을 연결하고 점프는 하지 않는다. 나머지 묶음은 클릭·키 조작 후 안정적인 액션 ID로 6-6 또는 7-3의 사냥 시작 단계로 이동한다. 일부는 점프 전 재확인을 명시적으로 켠다.

이 구조에서 참고할 점은 '특정 화면을 발견하면 현재 순서대로만 가는 것이 아니라, 준비 작업을 수행한 뒤 적절한 작업 상태로 복귀한다'는 것이다. 모든 감시 이미지가 같은 의미이거나 모든 묶음에 같은 재확인 값을 적용해야 한다는 뜻은 아니다. 13번의 비슷한 구성도 필드가 생략된 부분을 AI가 임의로 ON/OFF로 확정하지 않는다.

| 확인한 설정 | 제작 시 참고할 의미 |

| 5번 '다이쇼 입장'은 랜덤키 묶음 4개를 가진다. | 개별 키만 나열하지 말고 한 가지 입장 조작 흐름을 묶음 단위로 취급한다. |

## 이름과 PC 설정의 결합

`src/player/runtime_action_options.py`에는 정확한 이름 `호박`과 `로그인횟수`를 특별 처리하는 기존 규칙이 있다. 이름은 항상 단순 설명문이 아니다.

- `호박`은 PC의 `pumpkin_action_enabled` 토글과 연결된다. '남은호박'처럼 일부 글자가 들어간 이름까지 같은 동작이라고 판단하지 않는다.
- `로그인횟수`는 저장된 repeat_count보다 PC 설정의 `login_action_repeat_count`가 실행 횟수를 결정할 수 있다. JSON에 4라고 적혀 있다고 실제 PC도 반드시 4회라고 보고하지 않는다.
- 이름을 예쁘게 바꾼다는 이유로 이 결합을 끊지 않는다. 현재 MCP는 PC 설정 전체를 읽거나 수정하지 않으므로 필요하면 사용자에게 유효 설정을 확인한다.

## 이후 AI가 따를 편집 원칙

1. 전체 작업을 목적별로 나누고 상위·하위 관계를 먼저 정리한다.
2. 이미지와 키 입력의 역할을 구분한다. 키 입력에 의미 없는 이미지 대기 조건을 덧붙이지 않는다.
3. 같은 템플릿을 쓰더라도 대상 창과 항목의 검색 영역을 분리한다.
4. 액션 후 대기, 반복 간 대기, 키 유지 시간을 서로 구분한다.
5. 한 번의 조작을 여러 번 한 이유가 필요한 반복인지 실패 재시도인지 근거를 확인한다.
6. 스킵·복귀·점프·모니터링을 모든 동작에 일괄 적용하지 않는다. 목적과 조건이 있는 곳에만 구성한다.
7. 복귀할 작업 시작점을 안정적인 액션 ID로 표현한다. 예전 위치 기준 복귀가 있는 플랜은 순서를 함부로 변경하지 않는다.
8. 특화모드, 맵, 기존 인식 기준을 새 제작 기능과 섞어 수정하지 않는다.
9. 편집 후 영상→플랜, 플랜→영상의 두 방향으로 반복 대조한다. 수정하면 이전 완료 기록을 무효로 한다.
10. 현재 자료가 플랜뿐이면 이를 '제작 방식 참고 분석'으로 표시한다. 영상 프레임 증거를 만들어내거나 실제 플레이를 검증했다고 보고하지 않는다.

이 문서는 사용자가 원하는 제작 방식의 참고 예시이지, 플랜 이름에 따라 실행 로직을 바꾸는 규칙이나 학습된 전용 AI 모델이 아니다. 새로운 작업의 구체적 스샷·타이밍·예외는 해당 작업 자료로 다시 판단해야 한다.

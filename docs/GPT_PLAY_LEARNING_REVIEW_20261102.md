## 결론과 범위

GPT 플레이에 영구 경험 저장, 실패·성공 시도 기록, 조건부 구간 재사용, Arduino 시간 입력, 경험 UI, 동일 실행기 기반 후보 검수·신규 플랜 등록을 추가했다. 구현 후 재시작·저장 장애·중지·입력 불확실·등록 경로를 다시 검토하고 발견한 연결부 문제를 보완했다.

이것은 모델의 가중치를 재훈련하는 기능이 아니다. 작업별 기록과 화면 근거를 다음 GPT 판단에 전달하는 방식이다. 경험이 늘었다는 이유만으로 게임 이해나 성공률이 높아졌다고 표시하지 않는다.

**실제 보드·게임에서 이동, 전투, 클리어, 실패 후 복귀가 검증된 것은 아니다.** 메인 PC 비개입 조건을 지켰으며 COM 포트 연결·보드 업로드·게임 실행·배포를 하지 않았다. 실제 성능과 성공률을 보장하는 완료 보고가 아니다.

**계속 GPT 판단이 필요한 동적 전투를 완전한 독립 플랜으로 내보내는 부분은 미완료다.** 이번에 저장·재생하는 것은 시작·결과 조건이 정의된 검수 구간이다. 표현하지 못하는 필수 행동은 미완료로 남기며 완성 플랜처럼 등록하지 않는다.

## Arduino 경계

- 기존 KQ 짧은 탭과 일반 액션의 입력 시간은 변경하지 않았다.
- 새 GL1 프로토콜은 시간 지정 누르기 50~1000ms, 게임 키 최대 2개 동시 입력을 지원한다.
- 반복 입력은 최대 5회이며 유지 시간과 간격 합계가 1000ms 이하여야 한다.
- 시작·중지·개입 단축키 및 OS 전환 조합은 허용하지 않는다.
- 장치 측 유지 시간 제한과 약 300ms 생존 확인 제한을 코드에 두었다. 실제 해제 시간 상한은 물리 장치에서 측정하지 않았다.
- 실행 중 전체 시간에 직렬 통신 잠금을 잡지 않는다. 입력을 보낸 뒤 결과가 불명확해도 자동 재전송하지 않는다.
- 기존 연결 객체를 사용한다. COM 재연결, 다른 프로세스 포트 해제, 소프트웨어 입력 대체, 펌웨어 자동 업로드를 하지 않는다.
- 구형 펌웨어는 GL1 기능 조회에서 미지원으로 표시된다. 새 유지·동시 입력을 사용하려면 별도 테스트 보드에 호환 펌웨어를 준비하고 검증해야 한다.

## 저장과 한도

기본 위치: `%LOCALAPPDATA%\WinCro\gpt_play_memory\experience.db`.
화면 원본은 같은 폴더의 `evidence/<task_id>/`에 내용 해시로 저장한다.

- SQLite WAL·FULL 동기화, 세션/체크포인트 묶음 트랜잭션, 저장 후 재조회 비교를 사용한다.
- DB 손상이나 지원하지 않는 버전이면 원본을 삭제·초기화하지 않는다.
- 작업별 OS 잠금으로 같은 경험의 동시 실행을 막는다. 프로세스 종료 시 잠금은 OS가 해제한다.
- 새 실행 기준 기본 15분, 입력 500회, 시도 10회. 모델 턴 연장으로 예산이 초기화되지 않는다.
- 관찰 화면은 세션당 600장·128MB, 경험 저장소는 약 2GB 제한이다. 한도 도달 시 근거를 몰래 지우지 않고 입력을 중단한다.
- 등록된 GPT 플랜의 별도 실행 영수증은 최대 1000회분을 보관한다. 한도에 도달하면 기존 기록을 보존하며 새 실행을 차단한다.
- 경험 UI 조회는 배경 작업으로 수행하고 기록·작업 목록은 페이지 단위로 보여준다.
- 저장 중 상태 잠금이 걸려 있어도 UI 조회가 기다리지 않으며 중지 신호는 저장보다 먼저 전달된다.

외부 게임 입력과 디스크 기록은 하나의 원자 트랜잭션으로 묶을 수 없다. 전송 직후 전원 차단 같은 경우는 '불확실'로 보존하고 다음 실행에서 새 화면으로 확인하는 것이 이 구조의 처리 방식이다.

## 사용 순서

개발 코드의 변경 사항은 앱 프로세스를 다시 시작한 뒤 반영된다. 이번 작업에서는 사용 중인 앱을 종료하거나 재시작하지 않았다.

1. 테스트 PC에서 기존 Arduino 연결과 GL1 지원 여부를 확인한다. 이 작업은 보드를 자동 업데이트하지 않는다.
2. 화면녹화의 GPT 플레이를 열고 GPT 연결을 ON으로 둔다.
3. 새 목표면 `새 경험 시작`, 이어갈 목표면 위 경험 목록에서 기존 작업을 선택한다.
4. 대상 게임 창과 목표를 확인하고 `GPT 플레이 시작` 또는 `새 실행으로 경험 이어하기`를 누른다.
5. `경험 기록`에서 시도·전략·원인 후보·재사용 구간을 확인한다. 기록 이전/다음과 근거 장면 보기를 사용할 수 있다.
6. F10으로 개입, F11로 일시정지, F12로 중지한다. 세 버튼은 내부 탭을 바꿔도 위에 남는다.
7. `플랜 검수`에서 후보 입력 내용과 독립 연속 성공 횟수, 미해결 항목을 확인한다. 미해결 동작은 성공한 플랜처럼 등록하지 않는다.

시간·입력 예산이 끝나면 같은 세션의 계속 버튼으로 한도를 우회하지 않는다. 중지로 정리한 뒤 기존 경험을 선택하여 새 실행을 시작하면 저장된 경험과 후보를 이어받는다.

전체 회귀의 6개 건너뜀은 명시적으로 활성화해야 하는 네이티브 UI·입력·Codex 시험 모듈이다. 해당 시험은 이번 CI의 별도 격리 단계에서 실행했다. 전체 회귀의 경고 9개는 의존 라이브러리의 타입 정의 및 기존 `mss.mss` 사용 중단 예정 알림이다. 경고를 숨기거나 의존성을 임의로 바꾸지 않았다.
CI 아티팩트 `gpt-play-qa`에 시험 XML과 UI 스크린샷, `recording-analysis-execution`에 Codex 통신 시험 결과가 있다. UI 화면은 직접 열어 글자와 제어 버튼 배치를 확인했다.

### 최종 코드에서 발생한 실패 이력

Windows CI `41468237833` 첫 실행의 전체 회귀는 1,999개 통과, 3개 실패, 6개 건너뜀이었다. 실패는 기존 녹화 시작의 10초 초기화 시간 초과 1건, 녹화 분석의 8초 작업 완료 대기 초과 2건이었다. 녹화 시작 로그에는 DXGI `0x887A0004`와 캡처 방식 전환 메시지가 있었다. 이 로그만으로 세 실패가 같은 원인이라고 단정할 수 없다.

해당 실행의 앞선 녹화 분석 전용 시험과 GPT·UI·전송 시험은 통과했다. 녹화 분석 실패 2건은 로컬의 실제 파일 저장을 사용하는 무입력 시험에서 각각 약 0.1초에 통과했다. 새 GPT 시험 종료 후 잔존 실행 스레드도 확인되지 않았다. 환경 지연 가능성은 있지만, 이것만으로 근본 원인을 확정하거나 결함이 없다고 판단하지 않는다.

기존 녹화 동작이나 시험 제한 시간을 임의로 변경하지 않고 동일 코드로 CI를 재실행했다. 재실행에서는 실패 3건을 포함해 2,002개가 모두 통과했다. 녹화 시작·중지 통합 시험 시간은 2.46초였다. 첫 실패의 근본 원인은 확정되지 않았으며, 재실행 통과만으로 녹화 초기화 및 파일 처리의 지연 위험을 해결했다고 보고하지 않는다.

## 남은 한계와 미검증

- 실제 USB 단절·앱 강제 종료 시 키 해제 시간, 보드 호환성, 게임의 유지 입력·동시 입력 반응은 물리 시험이 남아 있다.
- 실제 GPT의 전략 개선, 첫 시도 대비 재도전 지연, 전투 성공률, 사망·부활·NPC 복귀는 실제 게임에서 확인해야 한다. 현재 숫자를 추정해서 제시하지 않는다.
- 경험 저장소의 2GB 제한은 앱 전체 사용량의 상한이 아니다. 별도 세션 근거·모델 실행 로그에도 저장 공간이 필요하며 기존 자료를 자동 삭제하지 않는다.
- 새 구간 인식은 지정된 창의 정렬된 작은 영역과 시작·종료 이미지 조건이다. UI 위치·크기·게임 장면이 크게 달라지면 재검수가 필요하다. 일반 이미지/동영상 인식 설정을 변경하여 억지로 맞추지 않았다.
- 임의 동적 적 추적, 일반 분기 그래프, GPT 연결 필수 플랜의 완전한 저장·재생은 이번 구현의 완료 범위가 아니다. 해당 행동이 필수이면 GPT가 계속 판단하거나 후보를 미완료로 남긴다.
- 성공한 후보만 만들어도 기존 플랜 전체 그룹 재생이 검증된 것은 아니다. 배포 PC와 실게임에서 별도 회귀가 필요하다.
- 기존 녹화 시험의 간헐적 초기화·작업 완료 시간 초과 3건은 동일 코드에서 재현되지 않았지만 원인이 확정되지 않았다. 실제 PC에서 재발한다면 당시 캡처 초기화·저장 지연을 별도 추적해야 한다.
- 새 기능은 보수적으로 입력을 차단한다. 저장·해제·권한이 불확실한 상황을 무시하며 계속 입력하는 방식은 사용하지 않는다.

## 보호 범위 확인

기존 재생 플랜·재생목록·녹화·지도 데이터를 이번 작업에서 수정하지 않았다. 원각/악귀문 특화모드 알고리즘과 일반 이미지/동영상 인식 경로도 수정하지 않았다. 일반 플레이어에는 새 액션 유형의 분기만 추가했으며 기존 액션을 자동 변환하지 않는다.

작업 시작 때부터 있던 별도 변경 파일은 되돌리거나 함께 커밋하지 않았다. 전체 CI는 명시한 코드 커밋 기준이며 별도 미커밋 변경까지 배포·검증 완료로 묶지 않는다. 격리 CI용 기능 브랜치에만 코드를 올렸다. 릴리즈 생성·버전 변경·전체 업데이트·메인 PC 조작은 하지 않았다.
